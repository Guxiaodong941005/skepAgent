## Scope check

Changed: `handlers/replan.ts`, the new `handlers/replan.test.ts`, and `replay.test.ts`. The
`replay.test.ts` change only removes the obsolete "keeps %s as the required non-mutating stub" case
and its now-unused `EventType` import, as assigned in the schedule. The remaining
"checks preconditions before dispatching" test is kept. `plan.ts` (SK-208), `barrier.ts`,
`lease.ts`, `apply.ts`, `state.ts`, the schemas and `test/helpers/*` are untouched. **OK.**

Purity and determinism: the handlers import only `canonicalJson` and the barrier helpers. There is
no I/O, clock or randomness. State stays plain JSON: the barrier, request records and
`last_checkpoint` are plain objects and arrays, and `awaiting` is derived from `stack_order`, not
from record iteration order.

Public-repo hygiene and D19: tests use `https://example.invalid/...` and builder agent IDs only.
There are no IPs, hostnames, emails or credentials.

## Findings

### Blocking

None.

### Non-blocking

1. **Coalesced requests skip the `payload.item` existence check.** This matches the brief, which
   only requires it when a barrier is opened. A coalesced request naming a non-existent item is
   then recorded in `barrier.requests` (only `summary`/`evidence_count` are stored, not the item),
   so there is no state inconsistency. Consider validating it in all three statuses for
   uniformity; it would be a reducer-version-neutral change only before the first live
   blackboard.
2. `replan.requested` in `interrupting`/`replanning` without a barrier returns `no_barrier`. It is
   unreachable from a valid log (the barrier is kept through `replanning`, D6), but it is tested
   on a constructed state, which is good defensive behaviour.
3. `barrier.closed` silently ignores a `missing` id with no item record (`if (item)`). This is also
   unreachable, because `awaiting` ⊆ items and activation clears the barrier. A thrown internal
   error, as `activatePlan` does for impossible states, would make an inconsistency louder.
4. `replan.ts` now carries D6/D16 comments. A one-line header citing ARCHITECTURE §5.5 and PRD §9.7
   would match `barrier.ts`.
