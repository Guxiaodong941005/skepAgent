* **Human intent builders** (`src/core/intents-human.ts`): `task.create` (budgets and approval
  re-derived, owner resolved from the registry), `task.cancel`, `plan.approve/reject` (locked
  plan, optional hash pin), `lease.revoke` (epoch-fenced), `human.decided`, `replan.request`. All

  in-process `Publisher` fallback with the human key from `device.toml`.
* **Commands:** `task new/cancel`, `plan approve/reject/show`, `lease revoke`, `decide`, `replan`,
  `agent start/stop`, printing `accepted`/`rejected` with `#seq` (rejected ⇒ exit 3) and `dropped`.
* **G5:** `Output.fail()` gives a single machine line with top-level `ok:false` plus the result;
  `skep sim run` uses it and now reports `seed` and `scenario`.

**Two problems block merging:**

* a merge conflict with current `main` (B1, trivial);
* the in-process fallback never prepares its own clone, so it does not work on a real controller
  (B2).

## Findings

### Blocking

**B1. Merge conflict in `src/cli/program.test.ts`.** Rebase onto `main` and keep only the `logs`
stub invocations, since `init`/`doctor`/`status`/`log` and all of this task's commands are
implemented. Re-run `npm test`.

**B2. The in-process fallback never prepares its clone.** `publishInProcess` and `replayLocal`
construct `BlackboardClone({ dir: paths.cliBlackboardClone, … })` and go straight to
`fetch`/`Publisher`, without `clone.init()`. Nothing in the product creates
`cliBlackboardClone`: `skep init --genesis` (SK-607) bootstraps into `paths.blackboardClone`, and
the daemon (SK-601) will use its own clone. On a real controller the fallback therefore fails.
For `publish`, every attempt is a `GitError` that the publisher retries with backoff
(`MAX_ATTEMPTS` 8) before failing. Until SK-601 lands this is the **only** write path, so `skep
task new`/`plan approve` cannot work.

**Required fix:**

* call `await clone.init()` before fetching (it is idempotent: SK-301 sets the remote, refspecs
  and mode 0700) in both `publishInProcess` and `replayLocal`;
* add a test that starts from a home **without** a CLI clone, with only `device.toml`, the trust
  root, the human key and a genesis-initialised bare remote, and publishes successfully through
  the fallback.

### Non-blocking

1. **`plan approve`/`reject` send no hash.** The builder supports a hash pin, but the command
   exposes no `--hash`/`--version`, so the decision applies to whatever plan is current at
   publish time. That is consistent with the PRD §15.2 command table, and a new version can only
   appear after a rejection. But the doc comment claims "pinned to the plan hash the human names".
   Either add `--hash <sha256:…>` (recommended for the human gate) or fix the comment, and in any
   case print the approved version and hash in the output.
2. `printMachine` (SK-604, merged after this branch started) and `output.result` are still two
   machine paths. Fold `printMachine` into `output.ts` while rebasing for B1 (SK-604 review note
   2).
