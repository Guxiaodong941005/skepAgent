## Findings

### Blocking

### Non-blocking

1. **`findRepo` normalization order.** `repoKey` strips `.git` before stripping trailing slashes,
   so `git@example.com:owner/app.git/` normalizes to `…/app.git` and doesn't match the configured
   `…/app.git` (which normalizes to `…/app`). Reproduced: it returns `null`. Strip the trailing
   slashes first, then `.git`, and add the case to the test.
2. `FrontMatterSplit.yamlStartsAt` is documented as "1-based line of the first YAML line" but holds
   the offset `1` (the first YAML line is file line 2). The arithmetic is correct. Fix the comment,
   or store `2` and add `line - 1`.
3. `dottedPath` yields a leading dot when a path starts with an array index (`.0.name`). This is
   unreachable with the current object-rooted schemas.
4. Treating YAML warnings as fatal is stricter than the brief. It's acceptable for trusted policy,
   but mention it in the `parseAgentMd` doc so an unexpected warning doesn't surprise anyone.
5. Test hygiene: `loadDeviceConfig`/`loadAgentMd` tests create temp dirs and never remove them. The
   ConfigError-path tests use `try { … } catch` with assertions only in `catch`. Some already call
   `expect.fail` in the `try`, but the bad-repo test in `device.test.ts` relies on the preceding
   `toThrow` line instead. Both are harmless.

## Suggested follow-ups

* Fix non-blocking 1 with a test. It's a two-line change, and it matters because `task.repo` values
  from the log are matched against this allowlist (PRD §11.5); a false negative there means a
  device refuses a legitimate task.
* SK-502 should call `parseChecksFile(text, "<base_commit>:.skep/checks.toml")` so errors name the
  commit, matching the `source` convention used in these tests.
