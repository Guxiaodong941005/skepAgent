### Non-blocking

1. **`execFileChecked` leaves the child's stdin open when `input` is omitted.** A child that reads
   stdin blocks until the timeout. Reproduced on the branch:
   `execFileChecked("cat", [], { env: { PATH }, timeoutMs: 1500, allowFailure: true })` ⇒
   `{ code: null, signal: "SIGTERM", timedOut: true }` after 1505 ms. Trusted checks (SK-502) run
   arbitrary repo commands, and tools that wait for EOF or probe stdin would hang until
   `timeout_sec`. Fix: `child.stdin?.end(opts.input)` when input is given, otherwise
   `child.stdin?.end()` (or `stdio: ["ignore", "pipe", "pipe"]`). Add a test with a child that reads
   stdin and no `input`.
2. **Buffer overflow throws even with `allowFailure`.** The brief says overflow throws "unless
   `allowFailure`". Node reports overflow with the string code `ERR_CHILD_PROCESS_STDIO_MAXBUFFER`,
   and the implementation treats every string code as a spawn failure that always throws.
   Reproduced: overflow with `allowFailure: true` rejects. Either special-case that code (return
   the truncated result) or document the deviation in the JSDoc. Also, the `maxBufferBytes` comment
   says "Combined stdout+stderr cap", but Node applies `maxBuffer` to each stream separately.
3. **`env` omitted ⇒ empty environment.** This is documented and tested, and it matches "no
   implicit merge". Note that Node still resolves the executable via the parent's `PATH` when
   `env.PATH` is absent, so `execFileChecked("git", ["--version"])` works, but the child itself
   then runs with no `PATH`/`HOME`. That's fine for SK-501's sanitized env. Callers should always
   pass an explicit env.
4. **Journal fails open on an attempt whose only line is torn.** `unfinishedAttempts` skips a file
   with zero complete records. If the first journaled step was torn by a crash, reconciliation
   never sees that attempt. Reconciliation should fail closed: report files that are non-empty but
   have no complete record as unfinished (SK-505 can handle "no last step").
5. **`Journal.path(key)` doesn't validate its key.** A `task` of `../x` would write outside the
   journal root, and `unfinishedAttempts` returns directory names as `TaskId` without checking
   `TASK_ID_RE`. Callers pass reducer-validated IDs, so this isn't exploitable today. A cheap check
   against `TASK_ID_RE`/`ITEM_ID_RE` (and skipping non-matching dirs) would make it robust.
6. **Concurrent appends to one attempt file aren't serialized.** `repairTornTail` followed by
   `appendFsync` could, in theory, truncate a line another writer in the same process is
   appending. The attempt runner is the single writer per attempt, so document that assumption
   (or serialize per key).
7. `safeJoin`'s lexical `escapes()` check treats a child named `..foo` as an escape
   (`path.relative` ⇒ `"..foo"`, which `startsWith("..")`). This fails closed, so it's harmless.
   Checking `fromRoot === ".." || fromRoot.startsWith(".." + path.sep)` would be exact.
8. The test "treats every terminal step as finished and ignores empty files" never creates an
   empty file. Either add one or rename the test.

## Suggested follow-ups

* Fix items 1 and 2 (with tests) in a small follow-up before SK-306/SK-502 start, or fold them into

* SK-505 (reconciliation): treat torn-only journals as unfinished (item 4).
