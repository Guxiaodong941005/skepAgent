### Non-blocking

1. **Ambient global git config still applies in production.** `NodeGitRunner` forwards `HOME`, so
   the user's `~/.gitconfig` affects every daemon `git` call: `core.hooksPath`, `commit.gpgsign`,
   `log.showSignature`, `gpg.ssh.revocationFile`, `url.*.insteadOf`, and so on. The tests hide this
   by stubbing `HOME` and setting `GIT_CONFIG_GLOBAL=/dev/null` in the fixture. Recommendation: have
   the runner set `GIT_CONFIG_NOSYSTEM=1` and `GIT_CONFIG_GLOBAL=/dev/null`, with an explicit opt-out
   for the cases that need user config. This also makes simulation runs reproducible.
2. **One argv for all SHAs.** `verifyCommits` puts every requested SHA on the `git log` command
   line. A long blackboard (thousands of commits) can exceed `ARG_MAX`. SK-203 (log reader) should
   batch the calls (e.g. 500 per call) or feed the SHAs via `--stdin`.
3. `NodeGitRunner` uses `maxBuffer` 16 MiB, which is fine for now. The log reader may need a larger
   value or streaming for full replays.
4. `test/helpers/git-fixture.ts` creates temp dirs under `<repo>/.skep-sim/` instead of
   `os.tmpdir()`. This is gitignored and cleaned up, so it's harmless. It does mean parallel test
   runs in one worktree share a parent directory.
5. A missing trust-root file is reported per commit as `unknown_key` rather than as an error. That
   is safe (fail closed), but the daemon should check the file exists at startup (`skep doctor`,
   SK-607) so the operator gets a clear message instead of "every commit is invalid".

## Suggested follow-ups

* Small fix (SK-102b, or fold into SK-203): isolate global/system git config in `NodeGitRunner`.
* SK-203: batch `verifyCommits` input.
* SK-607: trust-root presence check in `doctor`/daemon startup.
