## Verdict: **PASS_WITH_NOTES**

`createReplanDuty` fills SK-601's stub with the PRD §9.7 daemon side of a barrier.

* **Holder:**
  * every awaited lease held by this slot and flagged with the open barrier is interrupted
    **once** through `AttemptRunner.interrupt(key, barrierId)`; SK-504's pipeline then runs the
    ladder ⇒ mechanical snapshot ⇒ WIP push ⇒ `checkpoint.recorded`;
  * interruption is retried if the runner has not registered the attempt yet;
  * a voluntary checkpoint that finished just before the barrier was observed is **rebound** to
    the barrier from the journaled daemon snapshot (validated against item, epoch, attempt id and
    branch).
* **Owner:**
  * a **20-minute monotonic deadline** per barrier, starting at the owner's first observation
    (a restart or ownership transfer conservatively restarts it);
  * on expiry, a fenced `barrier.closed{missing = awaiting − settled}` that drops itself if a
    checkpoint lands during the write loop;
  * after an over-budget barrier settles into `escalated(replans)`, the owner is notified once
    with the redacted request summaries.
* **`publishReplanRequest`:** a model `replan_request` becomes `replan.requested` only with
  **locally verified** evidence (`EvidenceVerifier.verifyAll`). Evidence containing a secret
  pattern is dropped, the summary is redacted, and the intent is fenced on holder/epoch/attempt or
  owner generation.

Scenarios `replan-once`, `replan-escalate` (the third request escalates) and `missing-checkpoint`
(deadline ⇒ `barrier.closed`) are registered and pass, with same-seed replay.

The main note: **`publishReplanRequest` is not yet called by the attempt pipeline**, so an
agent-originated replan request never reaches the blackboard in production (note 1).

### Non-blocking

1. **An agent's `replan_request` is never published in production (PRD §9.7, S3).** When a work
   report carries `replan_request`, `AttemptRunner` (SK-504) currently proceeds as if it were a
   normal report. Required behaviour:
   * do **not** deliver;
   * call `publishReplanRequest` (verified evidence only);
   * on `accepted`, the barrier opens and the attempt checkpoints for it through this duty;
   * on `dropped` (no verified evidence), continue normally and journal that the request was
     ignored (§9.5: "a replan request with none is ignored (logged)").

   **This must land before SK-609**, since S3 depends on it. It is a small follow-up task touching
   `src/exec/attempt.ts` (+ test) and possibly `src/daemon/duties.ts`; assign it to codex.
2. **The evidence attempt key for owner-originated requests is a guess.** For `item: null`, or
   when the actor is the owner, `publishReplanRequest` verifies against the journal of
   `item ?? "W1"`, epoch `lease?.epoch ?? epochs[item] ?? 1`. Owner evidence (from the owner's
   plan/review invocation) is not in that attempt journal, so owner requests would usually verify
   nothing and be dropped. Take the evidence's journal key from the caller (the invocation that
   produced the report) instead of inferring it.
3. **The deadline restarts on owner restart** (in-memory `observed`). This is documented as
   conservative. Persisting the first observation in the owner's journal would keep the 20-minute
   promise across restarts; optional.
