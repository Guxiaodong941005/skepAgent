## Findings

### Blocking

**B1. The Linux unit's daemon cannot switch to the agent user.** `skepd` spawns each agent with
the agent user's `uid`/`gid` (`src/bin/skepd.ts` ⇒ `bindAgentRuntime`) and hands checkouts to it
with `chown`/`lchown` (`src/exec/worktree.ts`, `src/bin/skepd.ts`). That requires
`CAP_SETUID`/`CAP_SETGID`/`CAP_CHOWN` (or root). The unit runs `User=skep` with
`NoNewPrivileges=true` and no capabilities, so every attempt fails with `EPERM` at spawn or
hand-off.

**Fix:**

* `AmbientCapabilities=CAP_SETUID CAP_SETGID CAP_CHOWN`
* `CapabilityBoundingSet=CAP_SETUID CAP_SETGID CAP_CHOWN`
* keep `User=skep`; `NoNewPrivileges=true` stays compatible with ambient capabilities.

The runbook must explain why the daemon needs exactly these three.

**B2. The macOS LaunchAgent cannot switch users at all.** A per-user LaunchAgent has no way to
`setuid` to `skep-agent`, and macOS has no ambient-capability equivalent. As written, the plist
passes `--agent-user skep-agent` and will fail every attempt. **Architect decision (supersedes the
socket note in the SK-601 review):**

* On macOS, `skepd` runs as a **LaunchDaemon** under `root` (`/Library/LaunchDaemons`), with
  `--agent-user` the restricted agent account (PRD §1 / §11.4: "reusing the existing restricted
  user").
* The human's CLI then cannot use a 0600 socket owned by root. The socket must be **0660, group
  `skep`**, with the human's account in that group. This is the original ARCHITECTURE §12 wording
  ("the human's CLI user must be in the daemon group on the Mac").
* This needs a small code change: a socket group/mode option on SK-602's `IpcServer`, plus a
  `skepd` flag (`--socket-group <name>`). Until then, the CLI's in-process fallback publisher (fixed
  in SK-603) remains usable on the Mac.
* Record this as a follow-up task for SK-601/SK-602 and update ARCHITECTURE §12/§15 (architect).

The SK-608 plist must become a LaunchDaemon example with that model, and the runbook §1.3 must
match it.

**B3. The documented layout keeps the agent out of its worktree.** `SKEP_HOME` is 0700, owned by
the daemon user (`UMask=0077`, runbook "Layout"), and the role directory, and with it the worktree
root `<roleDir>/.skep/worktrees/…` (§7.5, SK-501), lives **inside** it
(`/var/lib/skep/roles/coding`, `~/.skep/roles/coding`). The agent user cannot traverse a 0700
parent, so even a correctly chowned checkout is unreachable, contradicting the runbook's own
sentence "the agent OS user can read its role directory and its worktrees". Separately, on Linux:

* `ProtectSystem=strict` + `ReadWritePaths=/var/lib/skep /etc/skep` makes the agent's home
  (`/var/lib/skep-agent`) **read-only** for the agent subprocess, which inherits the unit's mount
  namespace. The agent CLI's own config and session files (D19 local login) cannot be written.
* `ProtectHome=true` hides `/home`, which matters if the agent home is moved there.

**Fix:**

* Put role directories **outside** `SKEP_HOME` (e.g. `/var/lib/skep-roles/<role>`), with
  `0750 skep:skep-agent` on the path down to the worktree root, while keeping `SKEP_HOME`
  (`keys/`, `device.toml`, the blackboard clone) at 0700.
* Add the agent home to `ReadWritePaths`.
* Document the ownership table: daemon-only, agent-readable, agent-writable.
* Do the same on macOS.

### Non-blocking

1. `After=network.target` with fail-closed retries is fine. Mention `Wants=network-online.target`
   as optional for faster first sync.
2. The plist logs to `~/.skep/skepd.{out,err}.log`. With a root LaunchDaemon (B2), move the logs
   under `/Library/Logs/skep/` and note that they are redacted only for content `skepd` writes
   itself.
3. `runbook.test.ts` checks text presence only. Add an assertion that the units grant exactly the
   capabilities or privileges required by `--agent-user` (B1/B2), so a future edit cannot silently
   drop them.
