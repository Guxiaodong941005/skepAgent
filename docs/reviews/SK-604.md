## Verdict: **PASS_WITH_NOTES**

**`skep status`** asks the daemon over IPC (`status`). When the daemon is down, it replays the
CLI's own blackboard clone and says that liveness cannot be judged; it never calls a holder stale
without a heartbeat fetch. It renders the PRD §15.1 layout and covers F20:

* `--machine` is printed through `canonicalJson`;
* the freshness timestamp is labelled and serialized as **checked** (`checkedAtMonoMs`), because
  it also moves on an unchanged `ls-remote`;
* the 3 × interval … `staleMs` gap is labelled **`late`**, as the architect decision recorded in
  the brief requires.

Revoke suggestions appear only for `stale`/`lost` holders; parked leases and `late` holders get
none. Hint-channel health is shown as non-authoritative (D18), alarms are rendered, and nothing
about providers appears (D19).

**`skep log <task>`** shows the task's outcomes with actor and reason, honours `--from`, uses the
same daemon-or-local-replay path, and prints `--machine` canonically.

The notes concern a monotonic-clock fallback and a second machine-output path.

## Implementer note: judgement

**It accepts both a flat status result and `{ view, extras }`, reads the freshness timestamp as
`checkedAtMonoMs` or `fetchedAtMonoMs`, and accepts the log as an array or `{ outcomes }`.**
**Acceptable as a bridge, but SK-601 should fix one shape.** Two shapes and two key names are a
compatibility tolerance with no consumer yet. **Decision for SK-601:** the `status` handler
returns `{ view: StatusView, extras: { liveness, freshness: { checkedAtMonoMs, invalidCount,
reducerVersion }, hints, alarms, nowMonoMs } }` and `log` returns `{ outcomes }`. After SK-601
merges, drop the flat and `fetchedAtMonoMs` fallbacks here (small follow-up).

## Findings

### Blocking

None.

### Non-blocking

1. **Monotonic-clock mismatch in the fallback.** `extrasOf` falls back to the **CLI process's**
   `systemClock.monotonicMs()` when the daemon response has no `nowMonoMs`, and then computes the
   "checked" age as `nowMonoMs − checkedAtMonoMs`, with a timestamp taken from the **daemon's**
   monotonic clock. Monotonic clocks of different processes have unrelated origins, so the age is
   meaningless (it can even be negative). **Fix:** if `nowMonoMs` is absent, render the age as
   unknown. Better still, SK-601 sends ready-made ages (`checkedAgoMs`, per-agent
   `sinceChangeMs`, which the tracker already provides) instead of raw daemon monotonic
   timestamps.
2. **Two machine-output paths.** `printMachine` (canonical) next to `output.result` (insertion
   order). Consolidate in SK-603's `output.ts` (note above) so every command's `--machine` output
   is canonical and G5's `ok:false` envelope applies uniformly.
3. The local-replay fallback uses `paths.cliBlackboardClone`, which only exists once the
   in-process publisher (SK-603) has created it. When it is absent, the error message is
   actionable ("skepd is not running and the local blackboard could not be read"). That is fine.

## Follow-ups

* SK-601: the `status`/`log` result shapes above; send ages rather than raw monotonic timestamps
  (note 1).
* SK-603: fold `printMachine` into `output.ts` (note 2).
* After SK-601: remove the dual-shape tolerance here.
