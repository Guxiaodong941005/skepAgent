## Verdict: **PASS_WITH_NOTES**

`AttemptReconciler` implements ARCHITECTURE §11.4 / PRD §10.6 conservatively:

1. A **fresh** observation comes first.
2. For each unfinished attempt it stops recorded process groups (`invoked`, `check_started`):
   * it compares start tokens and **never signals a reused PID** (`process_reused`);
   * it **kills the group even when the leader token is empty or the leader is gone**, so orphan
     children die (F19).
3. A pending publication already seen on `main` is acknowledged by its **journaled event id**,
   even after its lease ended (F17).
4. Otherwise, any lease mismatch (epoch, holder, attempt id, plan version/hash) or a failed
   reverify ⇒ `stale`.
5. An unknown invocation or check outcome is **never re-run**. It becomes a persisted
   `work.failed{crash}`, or `checkpoint.recorded{invocation_state: unknown}` when a barrier
   interrupted the lease, so the barrier still settles.
6. A saved PR is checked by **number via `prState`** before anything else (G10; `findPr` only
   sees open PRs).
7. The rest is resumed through SK-504's idempotent `AttemptRunner` (remote-ref and PR lost-ack
   handling, scans before every publication).

`crash-every-step` crashes at every attempt step and every external publication boundary and
proves there are at most one push and one PR, exactly one execution per invocation, and zero
invariant violations. The SK-404 scenarios now use SK-503's `FakeCodeHost` (G3).

## Findings

### Blocking

None.

### Non-blocking

1. **Killing a pgid recorded with an empty start token can hit a reused group.** F19's rule (kill
   the group when the leader token is `""`) is right for orphans after a short outage. After a long
   downtime or a reboot, however, the same pgid number may belong to an unrelated group of the
   daemon user. Guard the kill: skip it if the device rebooted since the record (compare a
   journaled boot id or system boot time), or confirm via `/proc/<pid>/stat` / `ps` that at least
   one process in that pgid started after the journaled `ts_wall` of the `invoked` record.
2. **`stale` on a pending delivery while a barrier is open.** If the journal holds a pending
   `work.delivered` and the lease is now flagged (`interrupt` set), the reconciler returns `stale`
   to keep the event id. The barrier then waits for this holder's checkpoint until the owner's
   20-min deadline (`barrier.closed{missing}`). That is safe, but slower than settling it.
   Consider publishing `checkpoint.recorded{unknown}` (new event id) in that case, while keeping
   the old delivery id journaled for acknowledgement only.
3. **A human-merged or closed PR before `work.delivered` ⇒ `stale`.** If the human merged the PR
   between the push and the publication, the lease stays held with no event. That is rare, and the
   human can revoke, but `skep status` should point at it. Alternatively, publish
   `work.failed{crash}` with a clear detail so the lease ends.
4. Test runtime: the full suite is now ~2 min with the 3-seed sim default. That is fine; keep
   `crash-every-step` at a small step count.
