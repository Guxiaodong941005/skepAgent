## Verdict: **PASS_WITH_NOTES**

A careful, production-backed simulation harness.

* **`SimWorld.create`** builds bare blackboard and code remotes in a temp dir and a human-signed
  genesis. Each device gets a `SimNode` made of the **production** classes (`BlackboardClone`,
  `Publisher`, `Sync`, `HeartbeatWriter`, `NullHintChannel`), its own `FakeClock` view with
  skew/suspend, an isolated git runner, and a `duties(node, state) ⇒ Intent[]` hook.
* **`SimScheduler`** serializes real I/O and interleaves actors only at virtual sleeps, with
  seeded tie-breaking (`Rng.fork("schedule")`), including action-vs-timer ties at the same instant.
  Commit dates therefore never depend on host speed, and the same seed reproduces the same final
  tip in fresh directories.
* **`FaultyGitRunner`** injects seeded or scripted faults: failed fetch, competing push, lost ack
  after a real push, clock-driven delay, partition with heal.
* **`checkWorldInvariants`** covers:
  * invariant 1: incremental == full replay, and all nodes at the same tip agree byte for byte;
  * core `checkInvariants` (2–4, 6, 8, 9);
  * invariant 7: no heartbeat on `main`; `hb/*` refs are single signed orphans;
  * invariant 5 when a code host is attached.

  Violations carry seed, step and log dump.
* **`runScenario`** and the registry close the loop, and `empty` passes for several seeds.

## Test keys (extra check)

* `test/fixtures/keys/{human,mac,vps}` (+ `.pub`) are unencrypted ed25519 keys. The
  `test/fixtures/keys/README.md` states they are **public, test-only fixtures** that authenticate
  no real service and must never be used outside tests, and that the allowlist is restricted to
  that directory. It also mentions D19.
* `.gitleaks.toml` extends the default rules and allowlists **only** `paths = ['''^test/fixtures/keys/''']`.
  That is narrowly scoped; no rule is disabled.
* **Usage:** the only reference outside the fixture directory is `src/sim/world.ts`, which copies
  the keys into the world's own temp dir (0600) and builds a local trust root. The daemon, CLI,
  git, blackboard and exec code never reference them. The keys cannot be loaded by production
  paths.
* Caveat (note 1): because `world.ts` lives in `src/` and resolves the keys at
  `../../test/fixtures/keys/` relative to the module, `skep sim run` works only from a repository
  checkout, not from a published package whose `files` exclude `test/` (SK-610).

## Findings

### Blocking

None.

### Non-blocking

1. **`skep sim run` from an installed package.** Key paths are resolved relative to the source
   tree. Either ship the fixture keys inside the package under a clearly named `sim-fixtures/`
   directory (allowlisted, documented as test-only), or let `runScenario` accept a `keysDir`
   option and have the CLI fail with a clear message outside a checkout. Decide in SK-402, and make
   it explicit in SK-610's package `files`.
2. `world.ts` is ~600 lines, mixing the scheduler with world construction. Splitting
   `SimScheduler` into `scheduler.ts` would make SK-404/SK-505 changes easier to review. This is
   optional; there is no behaviour change.
3. The empty scenario run takes about 7 s for the sim suite. SK-404's 50-seed requirement across
   7 scenarios will be much slower. Keep per-scenario steps small, and consider
   `SKEP_SIM_SEEDS` (ARCHITECTURE §14) defaulting to fewer seeds in `npm test`, with 50 seeds in a
   dedicated run.
