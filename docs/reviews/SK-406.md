## Findings

### Blocking

None.

### Non-blocking

1. A thrown `RangeError` inside a handler propagates out of `replay`. That is intended for
   impossible states (fail loudly rather than record a wrong state). SK-601/SK-607 should catch it
   at the daemon boundary and enter read-only mode with an alarm, as for a reducer-version
   mismatch (§4.4), rather than crash-looping.
2. Per-agent `superseded` boot sets grow by one entry per restart for the observer's lifetime.
   That is negligible (restarts are rare), but a cap (e.g. the last 64) would bound it formally.
3. `alarms()` is pull-based. SK-601 must poll it after each `observe` batch and route new alarms
   to status/ntfy (F13 wiring).
