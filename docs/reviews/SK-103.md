* Date: 2026-10-06

## Verdict: **FAIL**

Tests and lint are green, and almost everything is well done. However, `VirtualTime.runNext()`,
an API the brief explicitly requires, has a real bug when a clock is suspended. It jumps virtual
time to `Infinity`, fires the suspended clock's timer, and leaves that clock's monotonic time at
`NaN`. The simulation scheduler (SK-401) is expected to drive time with `nextTimerAt()`/`runNext()`,
and the `sleep-wake-revoke` scenario suspends a daemon. So this would corrupt exactly the scenario
the fake clock exists for. The fix is small (see below).

## Findings

### Blocking

**B1. `runNext()` breaks when the earliest timer belongs to a suspended clock.**
`earliest()` picks timers by `effectiveAt(timer, this.time)`. That function is finite for a
suspended clock, because accrued suspension is measured up to "now". `runNext()` then computes the
fire time with `effectiveAt(due, +Infinity)`, which for a suspended owner is `Infinity`. The result
is `this.time = Infinity`, the suspended timer resolves, and `monotonicMs()` returns `NaN`.

Reproduction (run against the branch):

```ts
const vt = new VirtualTime(); const a = new FakeClock(vt);
let fired = false; a.sleep(1000).then(() => { fired = true; });
a.suspend();
await vt.runNext();
// observed: runNext=true, fired=true, vt.now=Infinity, a.monotonicMs()=NaN, a.suspended=true
// expected: runNext=false (no timer can fire while its clock is suspended), time unchanged
```

**B2 (same root cause). `nextTimerAt()` reports an unreachable time for a suspended clock's
timers.** With a 1,000 ms sleep on a clock suspended at t=0, it returns 1000 at t=0 and 1500 at
t=500. The target moves forward with time. A scheduler that loops `advance(nextTimerAt() - now)`
would spin forever without firing anything.

Suggested fix: treat timers whose owner is currently suspended as **not schedulable**. Skip them
in `earliest()`, `nextDue()` and `nextTimerAt()`. They become eligible again on `resume()`, when
their postponed time is finite. Add tests for: `runNext()` with only suspended timers (returns
`false`, time unchanged); `nextTimerAt()` ignoring suspended timers (returns `null` or the
earliest running timer); and a mixed case in which `runNext()` fires the awake clock's timer
first.

### Non-blocking

1. `Rng.chance(p)` documents "clamped to [0, 1]" but doesn't clamp. Behaviour is still correct
   (p ≤ 0 is never true, p ≥ 1 is always true), so either clamp or fix the comment.
2. `Rng.bytes` draws one float per byte via `int(0, 255)`. That's fine for determinism, but it
   wastes 24 of 32 bits. Not worth changing now. Any change would also alter every seeded stream,
   so if it ever changes, it must happen before golden sim fixtures exist (SK-401/402).
3. `VirtualTime.schedule()` is public. That's useful for the scheduler, but document that callers
   other than `FakeClock` get unsuspendable timers.
4. `flushMicrotasks()` uses a fixed three `Promise.resolve()` plus one `setImmediate`. Long `await`
   chains in daemon code could still run after the next timer. That's acceptable for now; SK-401
   should note it if interleavings look off.

### Evidence

* **B1 fixed.** `nextDue()` and `earliest()` now skip timers whose owner clock is suspended
  (`if (timer.owner?.suspended) continue`). My original reproduction against the fixed branch now
  prints `runNext=false fired=false vt.now=0 mono=0 suspended=true`. Before the fix it printed
  `true / true / Infinity / NaN`.
* **B2 fixed.** `nextTimerAt()` now delegates to `earliest()`, so it reports only runnable timers.
  The reproduction now gives `null` at t=0 and t=500 (previously 1000 and then 1500, a target that
  kept moving forward).
* **Requested tests exist and are meaningful** (`fake-clock.test.ts`):
  * "does not run a timer while its clock is suspended": `runNext()` returns `false`, time is
    unchanged, monotonic time stays 0, and the timer has not fired.
  * "ignores suspended clocks when reporting the next timer": `nextTimerAt()` returns `null` while
    suspended, both before and after `advance(500)`, and it reports an awake clock's timer
    correctly.
  * "runs the awake clock's timer before a suspended one's": the mixed case. The awake timer fires
    at 500, then `runNext()` returns `false`. After `resume()` the suspended timer becomes
    eligible at `now + 100` and fires with monotonic time 100, so the postponement is exact.
  * The existing `advance()`-based suspend tests still pass. The `effectiveAt()` postponement logic
    is unchanged, and the new skip only removes timers that could never fire anyway.
* **Non-blocking items addressed:** `Rng.chance` now clamps `p` and has a test. It still draws
  exactly one value per call, so seeded streams are unchanged. `VirtualTime.schedule()` now
  documents that timers without an owner can't be suspended.
* **Scope:** the fix touches only `src/sim/fake-clock.ts`, `src/sim/rng.ts` and their tests. No
  other files changed.
