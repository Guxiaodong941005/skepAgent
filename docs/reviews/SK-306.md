## Verdict: **PASS_WITH_NOTES**

`NativeRuntime` implements `RuntimeBackend` carefully:

* **Spawn:** detached spawn (`shell: false`, caller env only, D19), stdout and stderr to the same
  0600 log, prompt on stdin, and the parent's log descriptor released.
* **Start token:** Linux `/proc/<pid>/stat` field 22, parsed after the *last* `)` so `comm` with
  spaces, parentheses or newlines is safe. macOS uses `ps -o lstart=` with `LC_ALL=C TZ=UTC`.
* **Fail-closed setup:** token or stdin setup failures SIGKILL the group.
* **`wait()`** resolves only when the **whole process group** is gone, ignoring zombies. A leader
  exiting on SIGINT therefore cannot hide children that ignored it.
* **`isAlive`** compares the start token before probing the group (PID-reuse guard).

`runInterruptLadder` is a small, clock-driven SIGINT → grace → SIGTERM → term → SIGKILL ladder
that cancels losing timers. The real-process tests include INT-trapping grandchildren with and
without an early leader exit. One outcome label disagrees with the frozen adapter contract
(note 1); fix it before SK-504 records snapshots.

## Findings

### Blocking

None.

### Non-blocking

1. **The outcome label after SIGTERM contradicts the frozen contract.** `src/adapter/types.ts`
   defines `"interrupted"` = "stopped by SIGINT/cooperative stop" and `"killed"` = "**needed
   SIGTERM/SIGKILL**". `runInterruptLadder` returns `"interrupted"` when the group exits during
   the SIGTERM window, and the tests assert that ("uses the default 120 s grace, then gives
   SIGTERM 30 s" ⇒ `interrupted`). This flows into `snapshot.invocation_state` (PRD §9.7, §10.7),
   so a process that ignored SIGINT would be recorded as having stopped cooperatively. **Fix:**
   return `"killed"` once SIGTERM had to be sent, and update the two test expectations. This is a
   one-line change; do it before SK-504 builds snapshots.
2. **Empty start token for an already-exited leader (implementer's contract note).** When the
   leader is gone before its token can be read, the handle gets `startToken: ""`, which `isAlive`
   never matches. **Judgement: acceptable.** An empty token truthfully says "there is no leader
   left to re-adopt", and it can never match a future process, so it fails safe against PID reuse.
   Two caveats belong in SK-505 (restart reconciliation):
   * The leader can exit while its group still has children (tested: "returns a handle for
     surviving children when the leader exits before its token is read"). In the same daemon
     lifetime, `wait()` and `signalGroup` still cover them. After a restart, `isAlive(pgid, "")`
     is `false` even if orphans remain, so reconciliation should also run
     `signalGroup("SIGKILL")` on the recorded pgid (ESRCH is ignored) before declaring the attempt
     dead.
   * Journal the token exactly as returned (including `""`), and treat `""` as "not adoptable,
     kill the group".
3. `waitForGroup` polls every 25 ms by scanning `/proc/*/stat` (Linux) or `ps -axo` (macOS), but
   only after the leader has exited. That is fine for the MVP; a single process-group scan per
   tick would be cheaper if many checks finish with lingering children.
4. After SIGKILL the ladder waits for the group without a bound. A process stuck in
   uninterruptible sleep would hang the attempt. SK-504 should wrap the ladder in its own timeout
   and record `unknown` (PRD §9.7) if it expires.
