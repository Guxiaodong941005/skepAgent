## Findings

### Blocking

None.

### Non-blocking

1. **The hard-coded `DEFAULT_HOSTNAME = "github.com"`.** For a plain `owner/repo` the code passes
   `--hostname github.com`. That is a legitimate product default, not a personal host, but it is
   redundant: without `--hostname`, `gh api` uses gh's configured default host, which also
   supports GitHub Enterprise users. Prefer omitting `--hostname` unless a URL names a host.
2. **SSH-style repo references are not resolvable.** `repoSlug` handles `owner/repo` and
   `https://host/owner/repo(.git)`. An scp-style URL such as `git@host:owner/repo.git` (the form
   used in the device-config fixtures and PRD examples), or an allowlist **name** like `app`, is
   passed through unchanged. The ref API then returns 404, so `remoteBranchSha` returns `null`.
   SK-504's push check fails closed ("Code remote did not confirm…"), so nothing wrong is
   recorded, but delivery would be impossible for such repos. The other gh calls
   (`--repo=<value>`) have the same pre-existing gap. **Follow-up (SK-601 wiring, before SK-606):**
   resolve the allowlist entry to `{ host, owner/repo }` once (supporting `https://` and scp-style
   `git@host:owner/repo.git`) and pass that to `GhCodeHost`. Add a test per form.
3. The `bearer-token` rule also matches `Token <16+ chars>` and `Basic <16+ chars>`
   case-insensitively, so prose such as "token verification_failed_for_item" can be redacted in
   logs. That is a conservative false positive; acceptable, but worth a test pinning ordinary
   prose that must survive.
