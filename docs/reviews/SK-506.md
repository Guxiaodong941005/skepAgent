## Verdict: **PASS_WITH_NOTES**

`src/exec/redact.ts` is a pattern-only redactor, as ARCHITECTURE §16 and D19 require. It never
loads credentials or configuration. It has four rules:

* `private-key` blocks, failing closed through EOF when the footer is missing;
* provider-style API keys (`sk-…`, `AIza…`, `gsk_…`, `hf_…`, `AKIA`/`ASIA`…);
* GitHub tokens (`gh[pousr]_…`, `github_pat_…`);
* high-entropy `*_KEY=`/`*_TOKEN=`/`*_SECRET=` assignments, gitleaks-style: length ≥ 16, no
  whitespace, Shannon entropy ≥ 3.5, existing markers ignored.

Overlapping matches are merged into the union with the most specific rule, so no suffix can
escape. `findSecrets` returns rule and offsets only, never the secret. `Redactor.createStream()`
holds the unfinished line and any private-key block that crosses a line boundary, so tokens split
across chunks are never emitted half-redacted. The tests check every rule split at **every**
character boundary.

`Journal` gains an optional `redactor`. Records are scrubbed after a JSON round trip, which also
covers `toJSON` output, string by string, so the JSONL stays valid. Field-name collisions after
redaction throw instead of silently dropping data. The default stays the no-op SK-205 behaviour.

## Findings

### Blocking

None.

### Non-blocking

1. **A stream buffers indefinitely without a newline.** `push()` releases text only up to the
   last `\n`, so a CLI that emits megabytes on one line (minified output, binary) grows `pending`
   until `flush()`. Add a cap (e.g. 1 MiB) beyond which the buffer is redacted and released, while
   holding back the final ~256 characters, plus any open private-key block, so tokens straddling
   the cut are still caught.
2. **Coverage is intentionally narrow.** Generic bearer tokens (`Authorization: Bearer …`), JWTs
   (`eyJ…`), Slack (`xox[abp]-…`) and URL-embedded credentials (`https://user:pass@…`) are not
   covered. gitleaks still guards publications (§16), but journals and logs rely on this
   redactor. Adding these four patterns is cheap.
3. **Redacting journal records changes field values that the daemon may compare later** (e.g.
   an error `detail` that contained a token). That is intended; SK-504/SK-505 must never use
   redacted journal strings as identifiers (IDs and SHAs are unaffected by the rules).
4. Rule names are a closed union (`SecretRule`). Extending the rules later is an API change for
   anyone switching on `rule`; document that consumers should treat unknown rules as generic.
