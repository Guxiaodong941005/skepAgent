## Verdict: **PASS_WITH_NOTES**

`skep sim run --scenario <name> [--seed <n>] [--steps <n>]` replaces the stub. It calls SK-401's
`runScenario` and prints exactly one JSON line with `--machine`, or a short summary in human mode.

* An unknown scenario (`UnknownScenarioError`) is a usage error: exit 2, `code: "usage"`, and the
  message lists the available names.
* Invariant violations ⇒ exit 1. The violations are kept in the result (without the bulky log
  dump), and human mode adds a single `skep:` line on stderr.

To set exit 1 **without** a second machine line, the task added an optional `ctx.exitCode` to the
CLI context, honoured by `runCli`. That edit is outside SK-402's listed files; see the scope check.
It is additive and acceptable, with one envelope inconsistency (note 1).

## Findings

### Blocking

None.

### Non-blocking

1. **The machine envelope says `ok: true` while the exit code is 1.** With violations, stdout is
   `{"ok":true,"result":{"ok":false,…}}`, because `output.result()` always writes the success
   envelope. A wrapper checking the top-level `ok` (the §12 / `output.ts` contract: success ⇔
   `ok: true`) would treat a failed simulation as successful. **Fix:** add an
   `Output.failWithResult(data, err)`, or let `result()` take `ok`, so the line becomes
   `{"ok":false,"error":{"code":"invariant_violation","message":…},"result":{…}}`. That is still
   one line, and the top-level `ok` matches the exit code. Adjust the test. This touches
   `output.ts`; do it together with SK-603/SK-604, which will need the same pattern.
2. **Running from an installed package** (SK-401 note 1, assigned to this task): the command still
   relies on `test/fixtures/keys/` relative to the source tree, so outside a repository checkout
   `runScenario` fails with a file error. Catch it and print an actionable message ("sim requires
   a source checkout"), or decide the packaging in SK-610. This is not addressed here; carry it
   forward.
3. The default seed is `1` (documented in the option help). That is fine; the result echoes
   `finalTip` but not the seed. Including `seed` and `scenario` in the machine result would make
   logs self-describing.
