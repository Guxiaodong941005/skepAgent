## Verdict: **PASS_WITH_NOTES**

H12 and H13 are closed. When a work or fixup report carries `replan_request`, `AttemptRunner`
calls a replan handler **before** it commits, runs checks or creates a PR:

1. **Journal the request first.** It writes `replan_pending{event_id}`, so the request keeps one
   event id across a lost acknowledgement or a restart.
2. **Publish it.** `publishReplanRequest` runs with the invocation's own `evidenceKey` (H13: no
   `W1`/epoch-1 guess). Mismatched keys are dropped as `stale` before verification.
3. **Record the outcome**, then act on it:

| Outcome | What the attempt does |
|---|---|
| `accepted` | The handler runs the replan duty straight away. The duty interrupts this attempt for the new barrier through the single journal writer, and the attempt **checkpoints instead of delivering**. If no barrier interrupt has arrived, it throws rather than falling through to delivery. |
| `dropped(no_verified_evidence)` | Journals `replan_ignored` ("replan request ignored", §9.5) and continues normally, or checkpoints if it was interrupted meanwhile. |
| `failed` | Returns `pending`; the retry reuses the same event id. |
| fenced or rejected | Stale; nothing is delivered. |

There is one shared entry point for production and the simulator. `Duties` prefers
`runWithReplan` with `attemptReplanHandler`, and the new **agent-originated S3 scenario** goes
through that same callback with a real `file_span` evidence excerpt. It checkpoints and then
delivers plan v2.

## Findings

### Blocking

None.

### Non-blocking

1. **Layering.** `src/exec/attempt.ts` now imports `type ReplanRequestResult` from
   `src/daemon/replan.ts`, so `exec` depends on `daemon` (type-only, so there is no runtime
   cycle). Moving the result type into `src/exec/` or `src/core/` would keep the dependency
   direction clean. Optional.
2. **`agentReplanOnce` is exported but not in `scenarios/index.ts`**, which was not owned. It runs
   in its own test at the default seeds, but not in registry-driven sweeps such as
   `crash-every-step` or the 50-seed G1 sweep. Add one registry line (orchestrator), as was done
   for `stacked-delivery`.
3. **An accepted request without an observed barrier throws.** If the daemon's `current()` state
   does not yet include the accepted `replan.requested` when the handler runs the duty,
   `interrupt` is never called and the attempt throws `AttemptError`. This is safe (no delivery),
   and the journal ends at `replan_outcome`, so SK-505 reconciliation or the barrier deadline
   resolves it. However, the duties test only covers a publisher that applies the event before
   returning. Confirm on the real two-device run (SK-609) that this path is not hit, or make the
   attempt wait for the barrier on the next tick instead of throwing.
4. Calling `run(input)` without a handler on a replan report throws ("configure its handler").
   That is fail-safe, and production always uses `runWithReplan`.
