## Findings

### Blocking

**B1. `npm test` fails after the rebase.** `src/bin/skepd.test.ts` still asserts the "SK-602/SK-603
modules missing" error, which can no longer happen. **Fix:**

* switch `skepd.ts` to static imports of `IpcServer` and `intentFromSpec`;
* remove the dynamic-import fallback and its test;
* add a test that `runDaemon` wires `resolveIntent` to `intentFromSpec` and the IPC factory to
  `IpcServer`.

**B2. The `status` result does not match the merged `skep status` client (SK-604).**
`Daemon.status()` returns:

* a flat view with `freshness: { fetched_at_mono_ms, checked_age_ms, invalid_count }`
  (snake_case);
* `liveness` as an **object keyed by agent**, without interval;
* no `nowMonoMs`.

SK-604's decoder reads camelCase `freshness.checkedAtMonoMs`/`fetchedAtMonoMs`/`invalidCount`,
`liveness` as an **array** of `{ agent, cls, sinceChangeMs, intervalMs }`, and `nowMonoMs`.
Against the real daemon, `skep status` would therefore show the blackboard as **never checked**,
**no liveness**, **no `late` labels** and **no revoke suggestions**. Revoke suggestions are the
MVP's only path for stale holders (PRD S5, §6.4).

**Fix (shape recorded in the SK-604 review; ages instead of raw monotonic timestamps):**

```text
{ view: StatusView,
  extras: { liveness: [{ agent, cls, sinceChangeMs, intervalMs }],
            freshness: { checkedAgoMs, invalidCount, reducerVersion },
            hints, alarms, readOnly } }
```

* `intervalMs` = 60 000 with a held lease, else 300 000 (§8.1).
* SK-604's decoder needs a one-line acceptance of `checkedAgoMs` (orchestrator or this task; it is
  SK-604's merged file) so that it stops computing ages across processes (SK-604 review note 1).
* Add a test that runs `status` through the real `IpcServer` and SK-604's `decodeStatus` and shows
  liveness, a `late`/`stale` label and a revoke suggestion.

**B3 (small, required by the schedule). Register `crash-every-step`** in `scenarios/index.ts`
(one import + one entry).

### Non-blocking

1. **G12 remainder:** use `/usr/bin/id` in `resolveAgentUser` (one line in `sandbox-env.ts`, an
   SK-501 file; no other task in flight edits it).
2. **Socket user model (SK-602 note 1), still undecided.** `skepd` creates the socket 0600 as the
   daemon user. If the daemon runs as a separate service user on the controller, the human's CLI
   cannot connect and falls back to the in-process publisher (which works since SK-603's fix).
   **Architect decision for SK-608:** the MVP runs `skepd` as the **human's own user** on the
   controller (socket 0600 is then correct) and as a dedicated service user on worker devices
   (where no human CLI talks to it). The §12 wording "the human's CLI user must be in the daemon
   group" is to be replaced by that. Recorded here for SK-608.
3. **`GhCodeHost` repo resolution (SK-507 note 2)** is still open: the allowlist entry (an
   scp-style `git@host:owner/repo.git` or a name) is passed to `gh` unchanged. Fix before SK-606
   relies on PR operations against real repos: map the allowlist entry to `owner/repo` (+ host)
   in `skepd.ts` and pass that.
