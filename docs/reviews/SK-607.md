## Verdict: **FAIL**

Most of the task is good.

* **`skep init`** writes `device.toml` (0600, exclusive create), generates the daemon ed25519 key
  (0600 in a 0700 dir, minimal env), refuses to overwrite an existing config or key, prints the
  `allowed_signers` line, and with `--genesis` creates the human-signed root through SK-301's
  `createGenesis`.
* **`skep doctor`** runs:
  * device config, trust root and daemon principal checks;
  * signing-key mode;
  * AGENT.md per role, agent-user write access, checks file and repo allowlist;
  * pinned CLI presence/version **without reading any provider configuration (D19)**;
  * gitleaks presence (missing ⇒ fail, never skip);
  * **outbound-only** reachability of the blackboard and code remotes, with the relay only ever a
    warning (D18);
  * informational clock, disk space;
  * a full replay plus `checkInvariants`.
* **`NtfyNotifier`** redacts title, body and tags before posting, never throws on network failure,
  refuses redirects and times out after 10 s.

**One real bug blocks it (B1): the CLI version check uses a different pin format from the adapter
and the daemon**, so a device configured exactly as the SK-207 decision prescribes fails `doctor`.

## Findings

### Blocking

**B1. The CLI version pin format is inconsistent with the adapter and the daemon.**

* The SK-207 decision (`docs/spikes/adapter-codex.md`) says: set AGENT.md `cli_version` to the
  **entire** string `codex-cli <version>`.
* `CodexAdapter.probe()` returns that full line as `version`.
* SK-601's F14 gate compares `probe().version` with `cli_version` by exact equality.
* `doctor`'s `checkCli` instead extracts the first `x.y.z` from the output (`firstVersion`) and
  compares **that** with `cli_version`.

So a correctly pinned device (`cli_version: "codex-cli 0.160.0"`) fails `doctor` with "codex is
0.160.0, AGENT.md pins codex-cli 0.160.0". A device pinned the way `doctor` wants (`"0.160.0"`)
passes `doctor`, but the daemon will then refuse to invoke it. The test only covers the
`"1.2.3"` form.

**Required fix:** make `doctor` use the same comparison as the daemon:

* for `codex`, call `CodexAdapter.probe()` (or the identical rule: the exact output line matching
  `^codex-cli \S+$`) and compare the **whole line** with `cli_version`;
* for CLIs without an adapter yet (`claude`, `pi`), compare the exact trimmed first line of
  `--version` output and report "unsupported adapter" as a warning;
* add a test with the real `codex-cli <x.y.z>` format, plus a mismatch case.

### Non-blocking

1. **`init --genesis` does not write the local trust root.** Replay and `doctor` verify against
   `$SKEP_HOME/allowed_signers`, which must contain the `human` line and the `daemon:<device>`
   line. On the controller, `init --genesis` has both public keys (`--human-key` + `.pub`, and the
   new daemon key) but only prints the daemon line. Either write `allowed_signers` (0600) with
   both lines when absent, or print the exact two-line file to create. Otherwise the first
   `doctor` run after a genesis fails the replay check.
2. **Half-initialised state on a genesis failure.** The key and `device.toml` are written before
   `--genesis` runs. If genesis fails (for example an unusable human key), a re-run refuses
   because the key exists. Document the recovery (re-run `init` without `--genesis`, then a
   separate genesis step), or make genesis a separate subcommand.
3. **Non-ASCII ntfy titles.** HTTP header values must be Latin-1. A title with, say, an em dash
   makes `fetch` throw, and the notification is silently dropped (`delivered: false`). Encode the
   title (RFC 2047 `=?UTF-8?B?…?=`, which ntfy accepts) or use ntfy's JSON publish endpoint.
4. Test fixtures use `example.com`; the repo convention is `example.invalid`.
