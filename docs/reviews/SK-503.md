* **D19:** the gh host passes only a caller-supplied env (default `PATH` + `HOME`) and never reads

## Implementer contract notes: judgement

* **`PrInfo` = `{ number, url, head, base, title, state, mergeSha }`.** **Accepted.** §11.5 names
  `PrInfo` without fields. These are exactly what SK-504/SK-606 need: `pr_number`/`pr_url` for
  `work.delivered` (the URL is https, fitting the event schema), head and base for the stacked
  retarget, and `state`/`mergeSha` for `item.merged`. Record the shape in ARCHITECTURE §11.5 when
  SK-504 lands (architect docs follow-up).
* **The fake serves one bare repo and throws for any other.** **Accepted.** The sim uses one code
  repo per world, and failing loudly prevents two repos from silently sharing a ref namespace.
  Multi-repo scenarios can create one fake per repo.
* **gh `remoteBranchSha` = `git ls-remote <url from gh repo view>`.** **Acceptable for the MVP but
  fragile**; see note 2. SK-504 uses it for "code first, then record" (§7.5), so it must not hang
  or depend on a different credential path than the push.

## Findings

### Blocking

None.

### Non-blocking

1. **Option injection through leading `-`.** `assertRefName`/`assertRepo` do not reject values
   starting with `-`, and values are passed as separate argv elements after flags (`--base`,
   `<value>`). A base branch or repo name like `--web` could be parsed as an option, depending on
   gh's flag parser. Work branches are generated (`skep/<task>/<item>/e<n>`), but `base_branch`
   comes from human task input. **Fix:** reject a leading `-` in repo and ref names, and pass flag
   values as `--base=<v>`, `--head=<v>`, `--repo=<v>`, `--title=<v>`, `--body=<v>`, `--comment=<v>`.
2. **`remoteBranchSha` over HTTPS `ls-remote`.** For a private repo this needs git credentials,
   which come from the daemon user's git config or credential helpers. That is a different
   credential path from `gh`'s, and possibly from the SSH push in SK-501. Without
   `GIT_TERMINAL_PROMPT=0` it could also wait for input until the timeout. **Fix (before SK-504
   relies on it):** use `gh api repos/<owner>/<repo>/git/ref/heads/<branch>` (a 404 means null),
   which keeps one auth path. Alternatively, let SK-504 verify against the daemon's own mirror
   remote (SK-501) and use the code host only for PRs. Either way, set `GIT_TERMINAL_PROMPT=0`
   for any git call here.
3. **"One PR per head" is enforced only among open PRs.** The fake allows a new PR after the old
   one is closed (tested: "…allows a new PR after the old one closes"). Sim invariant 5 (§13.2)
   says "≤ 1 PR per head branch", with no state qualifier. Epoch-namespaced branches make reuse of a
   head unlikely, and a closed-then-recreated PR for the same head is exactly the duplicate that
   invariant should catch. **Fix:** refuse a second PR for a head in any state (or expose
   `listPrs()` so the SK-401/SK-404 invariant checker can count all of them) and adjust the test.
4. `findPr` queries only open PRs (`--state open`). If a crash happens after the PR was merged or
   closed by a human, recovery will not find it and may create a new one (on GitHub) or be refused
   (fake). SK-505 should call `prState` on the PR number recorded in the journal before falling
   back to `findPr`.
5. A headless device that authenticates `gh` via `GH_TOKEN` must pass it explicitly in `env`
   (`defaultEnv` deliberately omits it). That is the daemon's own code-host credential, not a
   provider credential, so D19 is not affected. Document it in the runbook (SK-608).
