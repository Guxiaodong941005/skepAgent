## Verdict: **PASS_WITH_NOTES**

The task implements the socket protocol of ARCHITECTURE §12.

* **Frames:** strict Zod frames, NDJSON, 1 MiB cap; `v` is checked **before** anything else
  (`protocol_version`), every other invalid frame is `bad_frame`, and the correlation id is
  recovered even from rejected frames.
* **Methods:** `status`, `log`, `publish`, `agent.start/stop`, `logs.tail`, `doctor`, `ping`, with
  strict per-method params.
* **`IntentSpec`:** a discriminated union of every CLI write kind; `publish` params validate it at
  the server.
* **Human signing:** `publish` with `signer: "human"` sends a `sign_request` (canonical base64
  payload, fresh `req` token) per write-loop attempt and waits for the matching `sign_result`. The
  private key never leaves the CLI, and `signerCallback` refuses a principal mismatch.
* **Socket:** 0600 inside a 0700 directory; a stale socket is replaced; responses, errors and
  streamed `logs.tail` chunks pass through the redactor (§16).
* **`logs.tail`** reports remote agents instead of reaching out (D18).
* **CLI:** `CliContext.connectDaemon` factory.

The notes concern permissions for a separate daemon user and two small consistency points.

## Implementer notes: judgement

* **CLI-facing `IntentSpec` kinds** (`task.create`, `plan.approve`, `decide`, `replan.request`, …)
  rather than raw event types, with the daemon re-deriving each event from state. **Accepted.**
  This is what §12 describes ("a serializable description … the daemon maps to a pure intent"):
  the CLI states the human's ask, and `pre`/revisions/hashes are computed from fresh state by the
  same builders SK-603 adds (`intentFromSpec`), so stale CLI views cannot leak into events.
* **`IpcHandlers.publish` types `intent` as `unknown`.** **Accepted.** The server already
  validates `params.intent` with `IntentSpecSchema` in `parseParams`. SK-601 must still parse it
  with `IntentSpecSchema` (cheap, and it keeps the handler type-safe); record this in SK-601's
  brief.
* **"No contract files were changed."** Correct for `src/core/**`. Note the small edit to
  `src/cli/program.ts` below.

## Findings

### Blocking

None.

### Non-blocking

1. **Socket permissions vs a separate daemon user.** The socket is 0600 in a 0700 directory, as
   the brief asked. ARCHITECTURE §12 also says "the human's CLI user must be in the daemon group
   on the Mac". If `skepd` runs as a dedicated user (recommended by §11.4/§3), 0600 makes the
   socket unreachable for the human's CLI. The fallback in-process publisher still works, but the
   daemon path does not. **Architect decision needed (SK-601/SK-608):** either run the CLI and
   daemon as the same user on the controller, or use 0660 on the socket with a dedicated group,
   and fix the §12 wording accordingly. The decision will be recorded when SK-601 wires the
   server.
2. **The sign timeout uses `setTimeout`** (wall clock). It is IPC liveness, not protocol timing,
   and is commented as such, but taking the injected `Clock` would keep the codebase rule uniform
   and make it simulator-friendly. This is minor.
3. **The CLI signs whatever commit bytes the daemon sends.** That is inherent to §7.4, and a
   compromised daemon user is out of scope (PRD §11.1). As cheap hardening, the CLI-side callback
   could parse the commit header and refuse anything that is not a single-parent commit whose
   message starts with the requested event type (`<type> <task> <event_id>`, §7.3). Optional.
4. `IpcServer.start()` derives the directory with `lastIndexOf("/")`; `path.dirname` would be
   clearer and portable.
